# Specialized geometry contracts

Read only when using equation curves, surfaces or exact offset jobs. Live system.describe remains authoritative.

### Spatial equation curves and exact surfaces

- Desktop Sphere placement and Center Position now use the center and keep it fixed on radius edits. The live `primitive.create` API still uses the legacy base position: for a default sphere centered at C, send C − (0, radius, 0). Do not change the interpretation of existing projects/scripts. Desktop interactive sphere previews are lightweight meshes; Apply builds the validated exact sphere before Done. Never treat a preview as a committed solid.
- Visible coplanar equation curves share one region arrangement, including annuli and areas genuinely closed by several open curves. Query fresh `sketch.regions` after edits or visibility changes; use the desired `region_indices`, not an assumed disk. Multi-curve Extrude/Revolve features freeze the entire profile, while single-curve linked features still rebuild. Confirm that snapshot behavior is acceptable if the user expects later parametric edits.
- Desktop direct Extrude of a whole exact planar face uses its native curved/inner boundary wires, including split sphere-shell rims. This is not curved-surface normal thickening and does not add a new Agent API. Use only face-extrusion methods actually advertised by the live catalog; never substitute a faceted disk for a curved rim. Symmetric planar depth means total depth.

- Use `curve.equation.preview` before `curve.equation.apply`, if present in the live catalog. Curves use a parameter `t`, three expressions, a finite increasing domain, `unit_mm` and a column-major affine transform. XYZ are world axes, not the camera's screen axes. In spherical mode theta is the XY azimuth from +X toward +Y, phi is the polar angle from +Z; `degrees` controls angular functions and spherical angles. Do not confuse a single implicit surface equation with a parametric curve.
- Reuse supplied domain and coordinate/angle/length conventions; ask only when a missing convention materially affects correctness. Sampling is bounded and approximate; do not claim a mathematical guarantee of continuity between arbitrary samples. Narrow the domain or simplify the equation if validation fails. A non-planar spatial curve is not a profile or solid; do not flatten it or send it to mesh exports. Use the saved project to preserve its editable definition.
- Draw Equation is a separate desktop tool. Coplanar equation lines can enclose selectable Sketch-like regions. If the live body reports nonempty `sketch.regions` and the catalog supports equation profiles, `feature.extrude` accepts that Curve ID in `sketch_id` with the returned region indices; do not invent a plane or assume a closed profile from visual appearance. Equation edits rebuild linked planar features and reject incompatible edits without changing the document.
- When the catalog exposes `surface.equation.preview/apply`, surfaces use parameters `u,v`, `u_domain`, `v_domain`, three XYZ or spherical expressions, `unit_mm`, affine `transform`, `resolution` (4..64 subdivisions per axis), and `fill`. Ask for domains, dimensions and whether to keep a sheet or fill a closed surface. B-spline interpolation is approximate between samples; it is not a symbolic exact solution. Fill accepts only an already closed valid surface and never adds caps to an open sheet. Use preview first; apply can edit an existing equation-surface `body_id` while preserving identity. Definitions and B-Rep survive project save/reopen.
- Extruding an equation surface means local-normal thickness, not translation along a fixed world direction. Use `feature.offset.start` with `SymmetricThickenSurface`, positive total thickness in millimeters, and `faces: []`; half the thickness goes on each side. `ThickenSurface` is one-sided. The desktop defaults to symmetric only for equation-surface Extrude. Ordinary Sketch/planar-Curve Extrude keeps its existing non-symmetric default. These offset results are frozen snapshots, not live dependencies on future equation edits.
- Exact offset/shell requires a body reporting `exact_brep: true`. New STEP imports preserve B-Rep; STL/OBJ and old mesh-only projects cannot recover their original smooth surfaces. Ask for the original STEP when needed. An open imported surface is a `surface`, not a solid.
- Choose `SurfaceOffset`, `HollowSolid` (select faces to remove), or `ThickenSurface` (open surface). Thickness and tolerance are in millimeters. Negative thickness points inward on outward-oriented solids. Inspect `topology_faces` from the current source; indices are zero-based and display bounds are approximate. Never invent face indices or reuse them after geometry changes.
- `feature.offset.start` creates a preview job, not a committed object. Keep its returned `job_id`, poll `feature.offset.status` with reasonable spacing, and commit only a `ready` job after checking the intended parameters. `feature.offset.cancel` affects only that matching job; it discards the eventual result, not necessarily the ongoing native computation. Failed jobs leave the document unchanged. Do not repeatedly start jobs or treat `computing` as success.
- Keep originals until verified. Offset results retain a frozen input B-Rep snapshot, not a live upstream dependency; re-editing the source does not rebuild existing offsets. “Arbitrary surfaces” is not a guarantee for every thickness or damaged model. Report native failures, preserve the original and revise thickness/face selection with the user.
